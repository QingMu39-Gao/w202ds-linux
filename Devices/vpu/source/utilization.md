# VPU 任务占用时间统计

codec 驱动新增只读 sysfs 文件，可从
`/sys/class/misc/sprd_vsp/device/utilization` 读取。权限为普通用户可读，
读取不获取 runtime PM 引用、不读取 VPU 寄存器，不为监控唤醒 VPU；频率由时钟框架查询。
旧内核没有该文件，消费者应显示不可用。

一行由空格分隔的 `key=value` 十进制字段组成：

| 字段 | 含义 |
| --- | --- |
| version | 当前格式版本 1 |
| generation | 本次 probe 的单调时间标识，用于发现模块重载 |
| total_ns | 自本次 probe 起的单调时间，纳秒；不包含系统挂起时间 |
| busy_ns | 原生解码 START 到首次完成／错误 IRQ，或成功停止复位的累计时间，含当前未结束任务 |
| untracked_ns | 旧用户态 MMIO 所有者持有上下文的累计时间，含当前未结束租约 |
| healthy | 1 表示未因复位失败进入 broken，0 时占用率不可信 |
| frequency_hz | 时钟框架报告的频率，Hz；不是实测吞吐或电源状态 |

同一行的时间计数在 IRQ 自旋锁下原子采样。消费者对同一 generation 的两次样本使用
`100 × Δbusy_ns / Δtotal_ns`，检查计数单调、时间增量大于零且忙碌增量不超过时间增量。
两端均须 healthy=1；窗口内 untracked_ns 增长时不提供百分比。
首次采样、格式不支持、读取失败、计数回退或模块重载均应重新建立基线，不当作 0%。

## 统计边界

这是原生 H.264/HEVC 共用解码核心的任务占用率，不是内部运算单元／带宽利用率。
原生执行的寄存器准备、软件解析、排队、显示和 CPU 工作不计入。
START 前取消不计忙碌；START 后取消、超时或信号打断不直接结束计时，
继续到 IRQ 或成功复位。IRQ 和复位的结束操作幂等，不重复累计；
复位失败保持 broken，让消费者报告不可用。

旧 ABI 允许用户态映射寄存器后直接 START，无法可靠测量开始时刻，因此整个
上下文租约（含 VMA 延长的生命周期）标为不可统计。不用上电时间、IRQ 数量或
CMD_COMPLETE 等待时间假装硬件忙碌时间。其他诊断模块不属于本接口的统计范围。

## 验收

编译检查不能代替实机验收。加载匹配的新模块后，应分别检查空闲、长任务跨采样、
连续原生 H.264/HEVC、取消、超时、失败复位、旧 MMIO 客户端、模块重载与系统挂起恢复。
空闲采样应为 0%，旧路径占用应为不可用；读取统计不应把 suspended 设备唤醒。
